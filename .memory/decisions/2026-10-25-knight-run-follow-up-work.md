# Decisions: 마창기사 후속 작업 후보

- Date: 2026-10-25
- Status: Confirmed
- Scope: 배포를 제외한 기존 게임 흐름·온라인 경쟁 기능의 추가 작업 후보를 정리한다. 이 문서 작성에서는 코드를 구현하지 않는다.

## D01. 후속 작업의 중심
- **Chosen**: 기존 플레이 흐름의 UX 개선과 현재 랭킹·비동기 PvP 기능 개선을 함께 다룬다. 장기 성장 동기를 위한 업적·임무·도감은 이번 중심 범위로 선택하지 않았다.
- **Rationale**: 사용자가 기존 게임을 더 편하게 이용하고 경쟁 결과를 더 잘 이해할 수 있는 개선에 초점을 맞췄다.

## D02. 후보 선정 및 우선순위
- **Chosen**: 코드에서 확인되는 개선점과 새 기능 아이디어를 모두 후보로 삼는다. 작은 작업을 먼저 배치하고 중간·큰 작업도 포함해 각 작업의 예상 크기와 선행 조건을 표시한다.
- **Rationale**: 빠르게 완료할 수 있는 일부터 검토하되, 장기적으로 필요한 개선도 함께 비교할 수 있다.

## D03. 입력 환경과 화면 방향
- **Chosen**: 가로 화면에서 키보드·마우스와 터치 입력을 모두 고려한다. 세로 화면 지원은 제외한다.
- **Rationale**: 현재 전투는 키보드와 터치를 지원하지만, 마을 보관함은 마우스 휠 스크롤에 의존한다. 세로 레이아웃은 기존 1280×720 화면 구조를 크게 바꿔야 한다.

## D04. 생성 이미지 시범 작업
- **Chosen**: AI 생성 이미지를 게임에 활용할 수 있다. 전투 화면에서 기사 캐릭터만 도형 대신 애니메이션 이미지로 바꾸고, 적은 기존 도형을 유지한다. 기사 애니메이션 후보 상태는 대기, 이동, 접촉 공격, 피격·밀림, 쓰러짐이다. 오디오는 추가하지 않는다.
- **Rationale**: 이미지 활용 가능성을 열면서도 첫 적용 대상을 기사 한 명으로 제한해 제작·연동 범위를 관리한다.

## D05. PvP 결과 및 경기 이력
- **Chosen**: 경기 결과와 최근 이력을 우선 개선한다. 마을에서 여는 기록 화면에 최신 10경기씩 표시하고 페이지를 이동할 수 있게 한다. 입력 로그를 재생하거나 장기 통계를 제공하는 기능은 선택하지 않았다.
- **Rationale**: 현재 결과는 대전 직후에만 보이고, SQL에는 경기 데이터가 있으나 경기 목록 조회 API와 화면이 없다.

## D06. PvP 데이터 보관
- **Chosen**: 경기 요약과 원본 입력 로그·전투 스냅샷의 보관 기간 및 정리 방식을 정하고 적용하는 작업을 후보에 포함한다. 구체적인 기간은 후속 계획에서 정한다.
- **Rationale**: 현재 경기 테이블에는 결과뿐 아니라 양쪽 스냅샷과 입력 로그가 저장되며 자동 정리 정책은 확인되지 않았다.

## D07. 저장 데이터 무결성
- **Chosen**: 클라이언트가 계산·제출하는 진행도, 골드, 장비, 능력치의 무결성을 높이는 서버 검증 또는 서버 권위형 저장 전환을 큰 규모 후보로 포함한다.
- **Rationale**: 기존 온라인 설계는 랭킹 전투 재생은 서버에서 검증하지만 게임 저장 데이터 자체는 클라이언트가 관리하는 위험을 수용했다. 사용자가 이를 재검토할 작업으로 추가하기로 했다.

## 자동 확인된 코드 근거
- 루트 `package.json`에는 테스트 스크립트가 없다. 루트 `test/`에는 브라우저·게임 도메인 테스트가 있고, 배포 워크플로는 프런트엔드 빌드와 API 테스트를 수행한다. 루트 테스트를 자동 검사에 연결하는 작업을 작은 안정성 후보로 둔다.
- `TownScene` 보관함은 마우스 휠로 스크롤하며 Phaser UI 버튼은 포인터 입력을 사용한다. 가로 터치 스크롤과 키보드 UI 조작·접근성은 추가 개선 여지가 있다.
- 랭킹 전광판은 스테이지/PvP 상위 5명을 번갈아 표시한다. PvP 결과 창은 승패와 레이팅 변동을 표시한다.
- `PvpMatches`에는 결과, 상대 스냅샷, 입력 로그가 저장되지만 현재 API에는 최근 경기 목록을 조회하는 경로가 없다.
- 최근 빌드 기록에는 500 kB 초과 청크 경고가 남아 있다. 번들 분할·초기 로딩 개선은 중간 규모 후보로 검토할 수 있다.

## 범위 밖 및 기존 결정의 유지
- Azure 리소스 생성·배포와 실환경 검증은 제외한다. 기존 온라인 배포 계획은 대상 구독·리소스 그룹이 정해지지 않아 보류 중이다.
- 기존 비동기 PvP 방식과 비시즌 레이팅 규칙은 변경 요청이 없는 한 유지한다.
- 세로 화면과 오디오 추가는 제외한다. 이미지 에셋은 위 D04의 기사 애니메이션 시범에 한해 허용한다.
- 예상 작업 크기는 코드베이스를 바탕으로 한 1차 추정이며, 세부 설계와 수용 조건은 후속 계획에서 확정한다.
